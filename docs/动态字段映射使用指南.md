# 动态字段映射使用指南

## 概述

本系统支持通过 **YAML 配置文件** 动态定义源表字段和索引字段的映射关系，无需修改代码即可适配不同的数据结构。

## 核心概念

### 1. 源表字段映射 (source-mappings)
定义从源数据库表中读取哪些字段，以及如何处理这些字段（包括关联表）。

### 2. 索引字段映射 (index-mappings)
定义索引中的字段结构，以及与源表字段的对应关系。

## 配置文件位置

```
src/main/resources/field-mapping.yml
```

## 配置文件结构

### 基本结构

```yaml
# 源表字段映射
source-mappings:
  表名1:
    fields: [字段列表]
    joins: [关联配置]
  表名2:
    fields: [字段列表]
    joins: [关联配置]

# 索引字段映射
index-mappings:
  索引名1:
    source-table: 源表名
    fields: [字段列表]
  索引名2:
    source-table: 源表名
    fields: [字段列表]
```

### 源表字段配置

```yaml
source-mappings:
  sample_data:
    fields:
      - name: id              # 数据库字段名
        type: LONG            # 字段类型: STRING, LONG, INTEGER, DOUBLE, BOOLEAN, DATE, TIMESTAMP
        alias: id             # 别名（可选，用于重命名）
        is-key: true          # 是否为主键
        required: true        # 是否必填
        default-value: null   # 默认值（可选）
        transform: null       # SQL 转换表达式（可选）
        order: 1              # 排序顺序
```

### 关联表配置

```yaml
source-mappings:
  orders:
    fields:
      - name: id
        type: LONG
        alias: order_id
        is-key: true
        order: 1
      - name: user_id
        type: LONG
        order: 2
    
    joins:
      - table: users          # 关联表名
        on-field: user_id     # 关联字段
        type: LEFT            # JOIN 类型: LEFT, INNER, RIGHT
        fields:               # 从关联表读取的字段
          - name: name
            type: STRING
            alias: user_name
            order: 3
```

### 索引字段配置

```yaml
index-mappings:
  sample_index:
    source-table: sample_data    # 对应的源表
    fields:
      - name: id                  # 索引字段名
        type: keyword             # ES 字段类型: text, keyword, long, double, date, boolean
        source-field: id          # 对应的源字段名（alias 或 name）
        searchable: false         # 是否可搜索
        sortable: true            # 是否可排序
        filterable: true          # 是否可过滤
        aggregatable: false       # 是否可聚合
        analyzer: null            # 分词器（可选）
        boost: 1.0                # 搜索权重（可选）
        format: null              # 日期格式（可选）
        order: 1                  # 排序顺序
```

## 使用场景

### 场景 1: 简单字段映射

```yaml
source-mappings:
  sample_data:
    fields:
      - name: id
        type: LONG
        alias: id
        is-key: true
        order: 1
      
      - name: name
        type: STRING
        alias: name
        order: 2
      
      - name: created_at
        type: TIMESTAMP
        alias: created_at
        order: 3
    
    joins: []

index-mappings:
  sample_index:
    source-table: sample_data
    fields:
      - name: id
        type: keyword
        source-field: id
        searchable: false
        sortable: true
        order: 1
      
      - name: name
        type: text
        source-field: name
        searchable: true
        sortable: true
        analyzer: standard
        order: 2
      
      - name: created_at
        type: date
        source-field: created_at
        format: "yyyy-MM-dd HH:mm:ss"
        order: 3
```

**生成的 SQL**:
```sql
SELECT sample_data.id AS id, 
       sample_data.name AS name, 
       sample_data.created_at AS created_at 
FROM sample_data 
ORDER BY sample_data.id
```

### 场景 2: 关联表查询

```yaml
source-mappings:
  orders:
    fields:
      - name: id
        type: LONG
        alias: order_id
        is-key: true
        order: 1
      
      - name: order_no
        type: STRING
        alias: order_no
        order: 2
      
      - name: user_id
        type: LONG
        alias: user_id
        order: 3
    
    joins:
      - table: users
        on-field: user_id
        type: LEFT
        fields:
          - name: name
            type: STRING
            alias: user_name
            order: 4
          
          - name: phone
            type: STRING
            alias: user_phone
            order: 5
```

**生成的 SQL**:
```sql
SELECT orders.id AS order_id, 
       orders.order_no AS order_no, 
       orders.user_id AS user_id, 
       users.name AS user_name, 
       users.phone AS user_phone 
FROM orders 
LEFT JOIN users ON orders.user_id = users.id 
ORDER BY orders.id
```

### 场景 3: 字段转换

```yaml
source-mappings:
  users:
    fields:
      - name: id
        type: LONG
        is-key: true
        order: 1
      
      - name: full_name
        type: STRING
        alias: full_name
        transform: "CONCAT(first_name, ' ', last_name)"
        order: 2
      
      - name: age
        type: INTEGER
        alias: age
        transform: "YEAR(CURRENT_DATE) - YEAR(birth_date)"
        order: 3
      
      - name: status_text
        type: STRING
        alias: status_text
        transform: "CASE WHEN status = 1 THEN 'Active' ELSE 'Inactive' END"
        order: 4
```

**生成的 SQL**:
```sql
SELECT users.id, 
       CONCAT(first_name, ' ', last_name) AS full_name,
       YEAR(CURRENT_DATE) - YEAR(birth_date) AS age,
       CASE WHEN status = 1 THEN 'Active' ELSE 'Inactive' END AS status_text
FROM users
ORDER BY users.id
```

## 核心组件

### 1. FieldMappingConfig

Spring Boot 配置类，自动加载 `field-mapping.yml`：

```java
@Autowired
private FieldMappingConfig fieldMappingConfig;

// 获取所有源表映射
Map<String, SourceTableMapping> sourceMappings = 
    fieldMappingConfig.getSourceMappings();

// 获取所有索引映射
Map<String, IndexMapping> indexMappings = 
    fieldMappingConfig.getIndexMappings();
```

### 2. FieldMappingService

提供便捷的查询方法：

```java
@Autowired
private FieldMappingService fieldMappingService;

// 获取源表的所有字段（包括关联表字段）
List<FieldConfig> allFields = 
    fieldMappingService.getSourceFields("sample_data");

// 获取源表的主表字段
List<FieldConfig> mainFields = 
    fieldMappingService.getMainFields("sample_data");

// 获取关联配置
List<JoinConfig> joins = 
    fieldMappingService.getJoinConfigs("sample_data");

// 获取主键字段
FieldConfig keyField = 
    fieldMappingService.getKeyField("sample_data");

// 获取索引字段
List<IndexFieldConfig> indexFields = 
    fieldMappingService.getIndexFields("sample_index");
```

### 3. DynamicSqlBuilder

动态生成 SQL：

```java
// 获取字段配置
List<FieldConfig> mainFields = fieldMappingService.getMainFields("orders");
List<JoinConfig> joins = fieldMappingService.getJoinConfigs("orders");
FieldConfig keyField = fieldMappingService.getKeyField("orders");

// 构建全量查询 SQL
String sql = DynamicSqlBuilder.buildFullQuerySql(
    "orders", 
    mainFields, 
    joins, 
    keyField
);

// 构建增量查询 SQL
String deltaSql = DynamicSqlBuilder.buildDeltaQuerySql(
    "orders", 
    mainFields, 
    joins, 
    "updated_at",
    keyField
);

// 获取字段名称列表
List<String> fieldNames = DynamicSqlBuilder.getFieldNames(allFields);
```

## 最佳实践

### 1. 字段命名规范

- **源表字段**: 使用数据库原始字段名（name）
- **字段别名**: 使用有意义的业务名称（alias）
- **索引字段**: 与 Elasticsearch 规范一致

### 2. 显示顺序

合理设置 `order` 以控制字段在 SELECT 语句中的顺序：
- 主键字段优先（order: 1）
- 业务关键字段其次（order: 2-10）
- 辅助字段最后（order: > 10）

### 3. 性能优化

- **JOIN 优化**: 避免过多的关联表，建议不超过3个
- **配置缓存**: `FieldMappingService` 在启动时加载，无需反复读取
- **索引优化**: 为关联字段创建数据库索引

### 4. 配置管理

**开发环境**:
```yaml
# field-mapping.yml
source-mappings:
  sample_data:
    fields: [...]
```

**生产环境**:
```yaml
# field-mapping-prod.yml
source-mappings:
  production_data:
    fields: [...]
```

使用 Spring Profile 加载不同配置：
```yaml
# application-prod.yml
spring:
  config:
    import: classpath:field-mapping-prod.yml
```

## 故障排查

### 问题 1: 配置未生效

**检查步骤**:
1. 确认 `field-mapping.yml` 在 `src/main/resources` 目录
2. 检查 YAML 语法是否正确（缩进、冒号）
3. 查看应用启动日志，确认配置已加载
4. 重启应用

### 问题 2: SQL 生成错误

**检查步骤**:
1. 验证 `on-field` 配置是否正确
2. 检查 `transform` SQL 语法
3. 确认表名和字段名大小写
4. 查看生成的 SQL 日志

### 问题 3: 字段类型不匹配

**解决方案**:
- 源表字段类型: `STRING`, `LONG`, `INTEGER`, `DOUBLE`, `BOOLEAN`, `DATE`, `TIMESTAMP`
- 索引字段类型: `text`, `keyword`, `long`, `integer`, `double`, `boolean`, `date`

## 配置文件优势

相比数据库表存储配置，YAML 配置文件有以下优势：

| 特性 | YAML 配置 | 数据库表 |
|------|----------|---------|
| **易读性** | ✅ 结构清晰，一目了然 | ❌ 需要查询才能查看 |
| **版本控制** | ✅ 可以用 Git 管理 | ❌ 难以追踪变更 |
| **部署简单** | ✅ 随代码一起部署 | ❌ 需要额外初始化 |
| **修改方便** | ✅ 直接编辑文件 | ❌ 需要 SQL 更新 |
| **环境隔离** | ✅ 不同环境不同文件 | ❌ 需要多套数据库 |
| **无需数据库** | ✅ 配置独立于数据 | ❌ 依赖数据库 |

## 总结

动态字段映射通过 YAML 配置提供了：
- ✅ 无需修改代码即可适配不同数据结构
- ✅ 支持复杂的关联查询
- ✅ 灵活的字段转换
- ✅ 易于维护和扩展
- ✅ 版本控制友好
- ✅ 部署简单

通过合理配置 `field-mapping.yml`，可以快速适配各种业务场景的索引需求。

架构设计说明（Java Batch）
## 文档目的与范围

本文件基于《需求说明》给出的业务目标，给出仅包含技术架构内容的实现方案：系统组件、数据与控制流、扩容与高可用策略、调度设计、部署拓扑、配置与可观测性，以及关键参数建议。实现技术以 Java + Spring Batch 为核心，配合可选的 Quartz 与 Kubernetes CronJob 调度。

## 技术栈与运行时

- Java 17+
- Spring Boot 3.x
- Spring Batch 5.x（核心批处理框架）
- Spring JDBC / DataSource（MySQL/Oracle 读取）
- CSV/JSON 读取器（FlatFileItemReader/自定义 Reader）
- Elasticsearch/日立 GetQuick Search 客户端（Writer）
- Quartz（集群化调度，JDBC JobStore）或 Kubernetes CronJob（容器化调度）
- 关系数据库：MySQL/Oracle（业务数据读取、Quartz 元数据、批处理元数据）
- 可选：Redis/ZooKeeper（分布式协调与锁，若不使用 Quartz 集群）
- 可观测性：Micrometer + Prometheus + Grafana，集中式日志（ELK/Cloud Logging）

## 体系结构概览

- API 层（可选）：暴露 REST 接口触发/查询任务（同步发起，异步执行）。
- Batch 核心：
  - Job 定义：全量索引 Job、增量索引 Job。
  - Step 设计：Reader → Processor → Writer（Chunk-Oriented）、索引检查 Step、清理/切换 Step。
  - 基础设施：JobLauncher、JobRepository（JDBC）、JobExplorer、JobParametersIncrementer。
- 任务调度：Quartz（集群，数据库持久化）或 Kubernetes CronJob（容器原生）。
- 数据源适配：RDB Reader（游标/分页）、文件 Reader（CSV/JSON）。
- 目标索引适配：ES Writer、GetQuick Writer、可选文件 Writer。
- 完整性检查与恢复：IndexCheckService、IndexRetryService（策略化重试与重建）。

## 组件设计

### Job 与 Step

- FullIndexJob：
  1) Cleanup/Prepare Step：删除旧索引或准备新索引别名。
  2) Read→Process→Write Step（Chunk-Oriented）：全量读取并写入目标索引。
  3) IntegrityCheck Step：检查记录数/校验和/采样查询等。
  4) AliasSwitch/Finalize Step：别名切换或最终化处理。

- IncrementalIndexJob：
  1) DeltaRead Step：基于时间戳/变更表/日志抓取增量数据（含增、改、删）。
  2) Read→Process→Write Step：按增量更新索引。
  3) IntegrityCheck Step：局部或整体一致性检查。
  4) ConditionalRebuild Step：按策略触发全量/局部重建。

### Readers / Processors / Writers（扩展点）

- Reader 扩展点：`DataSourceReader` 接口统一抽象，内置 MySQL/Oracle、CSV、JSON；可新增其他源（如 REST、消息队列）。
- Processor：领域清洗、映射与去重；支持无状态实现，便于并行。
- Writer 扩展点：`IndexWriter` 接口统一抽象，内置 ES、GetQuick；可插入批量写入、幂等 Upsert、删除标记处理。

### 完整性检查与恢复

- `IndexCheckService`：可配置指标（总量、校验和、采样查询、错误率阈值）。
- `IndexRetryService`：重试策略（固定/指数退避），失败阈值触发全量或局部重建。
- 幂等保障：基于业务主键 + 版本/更新时间做去重与覆盖，Writer 端 Upsert。

## 数据与控制流

1) 触发：定时调度（Quartz/K8s CronJob）或 API 触发。
2) Job 参数：数据源类型、时间窗口、索引目标、重建策略、并行度/分片参数等。
3) 执行：按 Step 顺序运行；Chunk 大小与并行策略可配置。
4) 校验：IntegrityCheck 根据策略判定通过/失败；失败进入重试/重建逻辑。
5) 输出：索引写入完成后可切换别名或发布事件。

## 扩容与高可用设计

### 进程内并行（单实例纵向扩展）

- 多线程 Step：`TaskExecutor` 并发读取与写入，适合 CPU/IO 混合工作负载。
- Chunk 配置：`chunkSize`、`commitInterval` 与 `concurrencyLimit` 调优以平衡吞吐与提交成本。

### 分片并行（单/多实例横向扩展）

- 本地分片（Local Partitioning）：单实例内将数据区间分片（按主键范围/哈希/日期）分给多个并发 Step 执行。
- 远程分片（Remote Partitioning）：主控 Step 将分片任务分发给远程工作器（可通过消息中间件或多 Pod），适合大规模全量构建。
- 分区策略：
  - 范围分区：按主键/时间范围切片（避免热点）。
  - 哈希分区：基于稳定哈希分配，便于幂等与重试。
  - 动态负载均衡：记录各分片处理耗时，下一周期调整分片大小。

### 多节点与互斥执行

- Quartz 集群：基于 JDBC JobStore，天然提供分布式调度、失效接管与互斥；同一 Trigger 在同一时刻仅有一实例获得执行权。
- 数据库锁/分布式锁：若使用 K8s CronJob，需要在 Job 启动时抢占分布式锁（如基于 DB/Redis），确保同一任务同一时刻仅执行一次。
- 幂等性：以业务主键 + 版本戳实现 Upsert；删除使用软删除标记或 Tombstone 事件，确保重复执行无副作用。

### 失败恢复与重试

- Step 级别重试：临时错误（网络/限流）按退避策略重试。
- Skippable：数据质量异常可跳过并记录；达阈值则失败并触发恢复策略。
- 重建策略：
  - 增量失败阈值超限 → 局部重建或自动全量重建。
  - 全量失败 → 先回滚别名切换，再重试或降级。

## 调度设计

### Quartz（推荐用于集群与复杂日程）

- JDBC JobStore：持久化 Trigger/Job 状态，支持 Misfire 策略与日历排除。
- 集群部署：多实例共享数据库表，基于悲观/乐观锁实现单次触发的互斥执行与故障转移。
- 关键配置：
  - 线程池大小：与并发 Job 数/Step 并行度匹配。
  - MisfirePolicy：全量任务“跳过并立即补偿” vs 增量任务“合并窗口后执行”。
  - 时区与夏令时：统一 UTC 或业务时区，避免切换异常。

### Kubernetes CronJob（推荐容器化与弹性场景）

- 容器镜像内置可执行 Job；由 CronJob 触发 Pod 运行。
- 并发策略：`Forbid`（禁止并发）、`Replace`（替换正在运行的实例）。
- 互斥与去重：需在应用内实现分布式锁或“租约”机制，防止多 Pod 并发执行同一逻辑。
- 失败重试：`backoffLimit` + 应用内重试；利用 Pod 重启与节点迁移实现弹性。

### API 触发与手动运营

- 即时触发：提供 REST 接口携带 JobParameters 发起临时任务（时间窗口、数据源、强制重建）。
- 运营面板：可选实现触发、取消、重试与进度/指标查看。

## 部署拓扑

- 单机模式（开发/测试）：
  - Spring Scheduler 或本地 Quartz，单实例内并行与本地分片。
- 集群模式（生产）：
  - Quartz 集群 + 多应用实例；或 K8s CronJob + 应用多副本（配合分布式锁）。
  - 远程分片：主控实例 + 多工作实例（或多 Pod），实现水平扩展。

## 配置与环境隔离

- Profile：`dev`/`test`/`prod` 区分数据源、索引目标、并行与分片参数。
- 可热切：非结构性参数（并行度/重试/阈值）支持配置中心下发与滚动生效。
- 机密管理：凭据存放于密钥管理（K8s Secret/云密钥服务）。

## 可观测性与运维

- 指标：
  - 吞吐：records/s（reader/processor/writer）、成功/失败计数、错误率。
  - 延迟：增量端到端延迟、Step/分片耗时分布。
  - 资源：CPU、内存、GC、线程池队列长度。
- 日志：结构化日志关联 jobId、step、partitionId、traceId。
- 追踪：可选 OpenTelemetry，为跨组件调用链打点。

## 兼容性与扩展点

- 数据源与索引目标通过 SPI/`@ConditionalOnProperty` 插件化装配。
- Reader/Writer/Processor 可独立演进；接口保持稳定。
- 新增目标系统（如另一个搜索引擎）只需实现 `IndexWriter` 并在配置中切换。

## 关键参数建议（初始值，需压测校准）

- Chunk 大小：1000（IO 为主可增大，CPU 为主适中）。
- 并行线程：2×CPU 核心数（观察外部系统限流再调优）。
- 分片数：数据量/目标吞吐预估 ÷ 单分片吞吐，向上取整；至少等于并行线程数。
- 重试：指数退避（初始 1s，上限 30s，最多 5 次）。
- 增量窗口：5 分钟；容忍迟到数据使用重叠窗口（如 1 分钟）防止漏数。

## 安全与访问控制（与架构相关）

- API 鉴权：OAuth2/JWT 或反向代理层鉴权。
- 最小权限：读取数据源的只读账号、索引目标的最小写权限。
- 审计：记录任务触发与执行结果，便于合规与追责。

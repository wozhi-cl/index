# 索引系统测试组合说明

## 📋 测试矩阵

系统支持多种数据源和索引目标的组合，以下是完整的测试矩阵：

### 支持的数据源（Reader）
1. **关系型数据库**
   - H2（内存数据库，测试环境）
   - MySQL（开发/生产环境）
   - Oracle（生产环境）

2. **文件系统**
   - CSV文件
   - JSON文件

### 支持的索引目标（Writer）
1. **Elasticsearch** - 搜索引擎
2. **File** - JSON文件输出
3. ~~**GetQuick**~~ - 日立付费服务（跳过，无公开文档）

## 🚀 运行测试

### 1. 运行单个测试类

在IDE中：
```
右键点击测试类 → Run 'TestClassName'
```

使用Maven：
```bash
# 运行特定测试类
mvn test -Dtest=FullIndexJobTest

# 运行特定测试方法
mvn test -Dtest=FullIndexJobTest#testFullIndexJobExecution
```

### 2. 运行测试套件

在IDE中：
```
右键点击 AllCombinationsTestSuite → Run 'AllCombinationsTestSuite'
```

使用Maven：
```bash
mvn test -Dtest=AllCombinationsTestSuite
```

### 3. 运行所有Job测试

```bash
# 运行 batch.job 包下的所有测试
mvn test -Dtest=com.company.index.batch.job.**

# 运行所有测试
mvn test
```

### 4. 使用脚本运行

```bash
# 运行所有组合测试
./scripts/run-all-combination-tests.sh

# 运行特定组合
./scripts/run-all-combination-tests.sh csv-file
```

## 🔧 测试配置

### AbstractJobTest 基类

所有测试类都继承自 `AbstractJobTest`，提供以下功能：

1. **通用测试方法**
   - `launchJobAndAssert()` - 执行Job并验证
   - `insertRdbTestData()` - 插入关系型数据库测试数据
   - `cleanupRdbTestData()` - 清理关系型数据库测试数据
   - `verifyIndexResult()` - 验证索引结果
   - `printTestSummary()` - 打印测试总结

2. **生命周期方法**
   - `@BeforeEach` - 准备测试数据
   - `@AfterEach` - 清理测试数据

3. **抽象方法（子类实现）**
   - `getDataSourceType()` - 获取数据源类型
   - `getIndexTargetType()` - 获取索引目标类型
   - `getTestProfile()` - 获取测试Profile
   - `prepareTestData()` - 准备测试数据
   - `cleanupTestData()` - 清理测试数据

### 测试数据

#### 关系型数据库（H2）
- 自动通过 `init-h2.sql` 初始化表结构
- 通过 `insertRdbTestData()` 插入测试数据
- 默认插入100条记录

#### CSV文件
- 位置: `src/test/resources/test-data/sample-data.csv`
- 格式: 标准CSV，包含20条记录
- 字段: id, name, description, status, created_at, updated_at

#### JSON文件
- 位置: `src/test/resources/test-data/sample-data.json`
- 格式: JSON数组，包含20条记录
- 字段: id, name, description, status, created_at, updated_at

## 📝 添加新的测试组合

### 步骤1: 创建配置文件

在 `src/test/resources/` 下创建新的配置文件：

```yaml
# application-test-<datasource>-<target>.yml

spring:
  datasource: ...

index:
  dataSource:
    type: <datasource-type>
    ...
  indexTarget:
    type: <target-type>
    ...
```

### 步骤2: 创建测试类

```java
@ActiveProfiles("test-<datasource>-<target>")
@TestPropertySource(properties = {
    "spring.batch.job.enabled=false",
    "index.dataSource.type=<datasource>",
    "index.indexTarget.type=<target>"
})
public class <DataSource>To<Target>JobTest extends AbstractJobTest {
    
    @Override
    protected String getDataSourceType() {
        return "<DataSource>";
    }

    @Override
    protected String getIndexTargetType() {
        return "<Target>";
    }

    @Override
    protected String getTestProfile() {
        return "test-<datasource>-<target>";
    }

    @Override
    protected void prepareTestData() throws Exception {
        // 准备测试数据
    }

    @Override
    protected void cleanupTestData() throws Exception {
        // 清理测试数据
    }

    @Test
    public void testFullIndexJob() throws Exception {
        // 测试全量索引
    }
}
```

### 步骤3: 添加到测试套件

在 `AllCombinationsTestSuite` 中添加新的测试类：

```java
@SelectClasses({
    // ... existing tests
    <DataSource>To<Target>JobTest.class
})
```

## ⚠️ 注意事项

### 1. Elasticsearch测试

Elasticsearch测试默认使用Mock，不需要真实的ES服务。如果要测试真实的ES：

1. 启动Elasticsearch服务
2. 移除测试类上的 `@Disabled` 注解
3. 配置正确的ES连接参数

### 2. MySQL/Oracle测试

MySQL和Oracle测试需要：
1. 相应的数据库服务运行
2. 正确的连接配置
3. 数据库表已创建
4. 更适合作为集成测试而非单元测试

### 3. 文件测试（CSV/JSON）

文件测试不支持增量索引，因为文件数据源没有时间戳字段。相关测试会跳过或标记为预期失败。

### 4. GetQuick测试

GetQuick是日立的付费服务，没有公开文档，因此跳过相关测试。

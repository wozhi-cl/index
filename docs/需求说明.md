索引管理系统需求文档
1. 目标与范围

本系统用于从多种数据源读取数据并建立可查询的索引，支持全量与增量两种索引模式，可通过定时调度与 API 方式触发执行，并在失败时具备重试与重建能力，确保索引数据的一致性与完整性。

2. 功能性需求
2.1 数据读取

1) 系统必须支持以下数据源类型：
   - 关系型数据库：MySQL、Oracle
   - 文件系统：CSV、JSON
2) 系统应支持通过统一接口扩展新的数据源类型。

2.2 索引写入

1) 系统必须支持以下索引目标：
   - Elasticsearch
   - 日立 GetQuick Search
2) 系统可选支持写入文件系统。
3) 系统应支持通过统一接口扩展新的索引目标类型。

2.3 索引任务

2.3.1 全量索引
1) 计划频率：每周执行一次。
2) 必须在任务开始前删除旧索引或使用新索引别名切换确保零碎片读取。
3) 必须从数据源读取全量数据并写入索引。
4) 必须在完成后执行索引完整性检查；检查失败时应自动重试或重新执行全量索引，直到成功。
5) 成功后执行成功后的处理

2.3.2 增量索引
1) 计划频率：每 5 分钟执行一次。
2) 必须支持三类变更：新增、修改、删除。
3) 必须按增量变更更新索引并在完成后执行完整性检查；检查失败时应支持自动触发全量重建，直到成功。
5) 成功后执行成功后的处理

2.4 调度与触发

1) 必须支持基于 Cron 表达式的定时调度（涵盖每周与每 5 分钟两类计划）。
2) 必须支持通过 API 动态触发全量或增量索引任务。
3) 应支持在不同运行模式下的调度：
   - 单机模式（适合开发/测试）
   - 集群/分布式模式（支持持久化、失败重试）
4) 必须支持对任务的启停与基本管理（如立即执行、取消、重试）。

2.5 API 接口

1) 必须提供以下 REST API：
   - 启动全量索引任务
   - 启动增量索引任务
   - 查询任务状态
2) API 必须支持传入任务参数（如时间范围、数据源类型、索引目标、是否强制重建等）。

2.6 任务可靠性与一致性

1) 必须支持任务失败自动重试（可配置重试次数与间隔）。
2) 必须提供索引完整性检查能力（如记录数/校验和/采样查询等方式，具体指标可配置）。
3) 必须支持重建策略配置：全量重建与增量重建。
4) 在分布式部署下，必须保证同一任务在同一时间仅被一个执行者处理，避免重复执行。

3. 非功能性需求

3.1 可扩展性
1) 应通过标准化接口支持快速接入新的数据源与索引目标。

3.2 可用性与可靠性
1) 任务失败应自动重试并可人工重试。
2) 索引完整性检查失败时应提供可配置的自动化恢复策略。

3.3 性能与容量
1) 系统应支持水平扩展以处理更高数据量与更高索引吞吐。
2) 在典型负载下，增量索引的端到端延迟应与调度频率匹配（例如 5 分钟窗口内可完成一次增量周期）。

3.4 维护性
1) 系统应采用模块化设计以便于独立演进与维护（Reader/Writer/Job/Scheduler 分离）。

3.5 配置与环境
1) 必须支持通过环境配置启用不同运行环境（如使用不同数据源或索引目标）。
2) 配置项应支持无重启生效或在运维窗口内滚动发布。

3.6 部署与分布式
1) 系统应支持在单机与分布式环境部署，并在分布式场景下保证任务的幂等与互斥执行。

3.7 安全与审计（如适用）
1) API 调用应支持鉴权与最小权限控制。
2) 任务触发与结果应可审计（至少保留任务请求与执行结果记录）。
